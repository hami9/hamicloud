## 1. Scope and Implementation Reality

This document records the progress toward Milestone M2. As identified during engineering review, the current implementation is a development-only prototype and **does not meet the Roadmap exit criteria for M2 closure**:

1. **No Kubernetes Job / Pod Execution:** Jobs are executed directly on the host machine using `os/exec` via `LocalProcessJobRunner`. There is no Kubernetes client, no Job or Pod object creation, and no container sandboxing.
2. **No Container Isolation:** The API checks image digests against the approved registry allowlist, but the local runner executes host processes directly without downloading or isolating container images.
3. **Local Host Probing:** Service releases are probed on `127.0.0.1:{port}` with no container lifecycle management.
4. **NATS JetStream Listener Implemented:** The Go runtime scheduler and executor listen for NATS JetStream events for non-blocking wakeups while maintaining periodic DB polling.
5. **No Live Recorded Demos:** The required duplicate submission, worker restart, and failed job demos have not yet been recorded.

Consequently, **Milestone M2 remains OPEN in `MASTER-PLAN.md`**.

---

## 2. Implemented Capabilities (Development Baseline)

The following building blocks have been implemented for early validation:

- **Durable Intent & Lease Fencing:** PostgreSQL `execution_intents` and `job_attempts` tables enforce monotonic lease epochs, worker IDs, and attempt numbers with `SELECT ... FOR UPDATE SKIP LOCKED`.
- **Job Admission & Backoff Scheduler:** The Go scheduler admits queued jobs, tracks attempt numbers against `max_retries`, and enforces exponential retry backoff.
- **NATS JetStream Event Listener:** Event-driven wake-ups (`bus.EventListener`) connected to scheduler and executor loops with graceful degradation to periodic DB polling on disconnection.
- **Local Host Job Execution (Development Only):** `LocalProcessJobRunner` executes host command arguments with sanitized environments (no host database credentials exposed) and writes stdout/stderr to a configured absolute `ARTIFACTS_DIR`.
- **Authorized Output Retrieval:** `GET /v1/jobs/{job_id}/output` serves execution artifacts from `ARTIFACTS_DIR` with workspace isolation (HTTP 404 for non-members) and state locking (HTTP 409 while actively running). Missing artifacts return HTTP 404 (never fabricated).
- **Graceful Cancellation Monitoring:** In-flight cancellation polling signals running processes and finalizes state transitions to `CANCELLED`.
- **Deterministic Service Rollbacks:** `POST /v1/apps/{app}/rollbacks` clones target release configurations, increments generation, and creates a new healthy release intent.
