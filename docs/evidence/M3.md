## 2. Implemented Components & Deliverables

1. **Schema & Database Migrations (`migrations/versions/0005_source_builds_and_repos.py`):**
   - `repositories`: workspace-isolated Git repository registrations (`workspace_id` FK CASCADE, `name`, `repo_url`, `webhook_secret`, `default_branch`).
   - `applications`: added columns `repository_id` (FK to `repositories`), `dockerfile_path`, `context_dir`, `git_branch`.
   - `releases`: added columns `repository_id`, `commit_sha`, `git_ref`, `commit_message`, `build_duration_ms`, `build_logs`.
   - `webhook_deliveries`: webhook delivery deduplication log with unique constraint `uq_webhook_delivery_repo_delivery`.
   - Applied cleanly with zero drift verified by `alembic check`.

2. **Control Plane Models & Pydantic Schemas (`apps/api/app/`):**
   - SQLAlchemy models: `Repository` in `app/models/repository.py`, `WebhookDelivery` in `app/models/webhook_delivery.py`.
   - Schemas: `CreateRepositoryRequest`, `RepositoryResponse`, `TriggerBuildRequest`, `UpdateApplicationRequest` in `app/schemas/`.

3. **API Endpoints (`apps/api/app/api/v1/`):**
   - `POST /v1/workspaces/{workspace_id}/repositories`: Register Git repository.
   - `GET /v1/workspaces/{workspace_id}/repositories`: List connected repositories.
   - `GET /v1/repositories/{repository_id}`: Inspect repository metadata.
   - `POST /v1/webhooks/github/{repository_id}`: HMAC-SHA256 verified webhook endpoint with delivery deduplication and push event release creation.
   - `POST /v1/apps/{app_id}/builds`: Manual source build dispatch.
   - `POST /v1/releases/{release_id}/process-build`: Build processor callback handling build completion and failure transitions.
   - `PATCH /v1/apps/{app_id}`: Link existing repositories and update application metadata.

4. **Runtime Admission Protection (`runtime/internal/store/postgres.go`):**
   - Hardened `ScanUnadmittedReleases` in the Go runtime store with `AND r.image_digest != 'pending'`.
   - Ensures releases queued for source building are not prematurely admitted for container scheduling until an image digest is published.

5. **Contracts & Event Schemas (`contracts/events/`):**
   - Added `app.build.requested.v1.json` and `app.build.completed.v1.json` matching transactional outbox topics.
   - Verified 100% compliant with `test_contracts.py`.

6. **OpenAPI Specification Sync (`contracts/openapi/v1.yaml`):**
   - Documented all M3 routes, headers (`X-Hub-Signature-256`, `X-GitHub-Delivery`), and schemas.
   - Validated against OpenAPI 3.1 schema via `openapi-spec-validator` (0 errors).

7. **Minimalist UI UX Pro Max Web Dashboard (`apps/web`):**
   - **Repository Card:** Surfaces connected Git remote, default branch, and webhook URL with HMAC protection status.
   - **Trigger Source Build Form:** Allows developers to dispatch builds from arbitrary branches or commit SHAs with instant feedback.
   - **Releases & Revision History Table:** Displays Git branch pills, commit SHA badges, commit messages, build duration, and status indicators.
   - **Interactive Build Simulation:** Single-click builder simulation actions (`✓ Pass Build` and `✕ Fail Build`) for instant end-to-end local testing.
