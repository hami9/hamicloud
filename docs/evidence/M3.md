## 2. Implemented Components & Deliverables

1. **Schema & Database Migrations (`migrations/versions/0005_source_builds_and_repos.py`):**
   - `repositories`: workspace-isolated Git repository registrations (`workspace_id` FK CASCADE, `name`, `repo_url`, `webhook_secret`, `default_branch`).
   - `applications`: added columns `repository_id` (FK to `repositories`), `dockerfile_path`, `context_dir`, `git_branch`.
   - `releases`: added columns `repository_id`, `commit_sha`, `git_ref`, `commit_message`, `build_duration_ms`, `build_logs`.
   - `webhook_deliveries`: webhook delivery deduplication log with unique constraint `uq_webhook_delivery_repo_delivery`.

2. **Control Plane API Endpoints & Schemas (`apps/api/app/`):**
   - `POST /v1/workspaces/{workspace_id}/repositories`: Register Git repository with exact host allowlist verification and caller workspace authorization.
   - `GET /v1/workspaces/{workspace_id}/repositories`: List connected repositories.
   - `GET /v1/repositories/{repository_id}`: Inspect repository metadata.
   - `POST /v1/webhooks/github/{repository_id}`: HMAC-SHA256 verified webhook endpoint with delivery deduplication and push event release creation (`status = REQUESTED`, `image_digest = 'pending'`).
   - `POST /v1/apps/{app_id}/builds`: Manual source build dispatch with optional `commit_sha`, `git_ref`, `commit_message`, `port`, and `health_path`.
   - `PATCH /v1/apps/{app_id}`: Link existing repositories and update application build settings (`dockerfile_path`, `context_dir`, `git_branch`).

3. **Isolated Build Reconciler & OCI Registry Pipeline (`runtime/internal/reconciler/build_reconciler.go`, `runtime/internal/store/postgres.go`):**
   - `ClaimNextBuildRelease`: Atomically claims pending source-backed releases (`status = 'REQUESTED' AND image_digest = 'pending'`) with `FOR UPDATE OF r SKIP LOCKED` and transitions to `BUILDING`.
   - `IsolatedBuildKitRunner`: Clones source repository into an isolated temporary workspace (`os.MkdirTemp`), checks out and verifies the target commit SHA (`git rev-parse HEAD`), enforces repository root boundary checks (`verifyPathWithinRoot`) on `dockerfile_path` and `context_dir` to prevent path traversal, builds the container image via BuildKit/Docker, pushes to the local OCI registry (`localhost:5000`), resolves the immutable `@sha256:...` manifest digest, and scrubs credentials/tokens from build output (`redactBuildLogs`).
   - `MarkBuildSucceeded`: Transitions release from `BUILDING` to `IMAGE_READY` with the immutable `localhost:5000/<ws>/<app>@sha256:...` digest, increments `applications.desired_generation` so the scheduler admits the built release for Kubernetes rollout, and emits transactional outbox event `app.build.completed.v1`.
   - `MarkBuildFailed`: Transitions release from `BUILDING` to `BUILD_FAILED` with failure reason and redacted logs without modifying `applications.desired_generation` or `applications.current_release_id`, and emits `app.build.completed.v1`.
   - `ScanUnadmittedReleases`: Filters `r2.image_digest != 'pending'` in both superseding and latest-release selection subqueries so pending or failed (`BUILD_FAILED`) builds never block or supersede currently serving releases.

4. **Local OCI Registry & BuildKit Compose Infrastructure (`deploy/compose/`):**
   - Added `registry` (`registry:2`, container `hamicloud-registry` on port `5000`) and `buildkit` (`moby/buildkit:latest`, container `hamicloud-buildkit` on port `1234` with `deploy/compose/buildkitd.toml`) to `deploy/compose/docker-compose.yml`.
   - Connected `hamicloud-registry` to the Kind cluster network with `/etc/containerd/certs.d/localhost:5000/hosts.toml` configured on `desktop-control-plane`.
