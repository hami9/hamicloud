- [x] **Two-workspace negative tests pass across API, logs, artifacts, secrets and network:**
  - Verified via automated test matrix and live multi-user demo (`scripts/demos/m4_multi_user_isolation.ps1`, raw evidence in [`docs/evidence/demos/raw/m4-multi-user-isolation/`](demos/raw/m4-multi-user-isolation/)):
    - **API & Metadata Enumeration Prevention:** Non-member (`bob`, OWNER of Workspace B `806bcc5f-f3e1-4d13-9a0c-f69852bcf135`) attempting to read or mutate Workspace A (`2a9ea502-1597-4566-91aa-30ccd2cb9e12`) applications, deployments, releases, jobs, operations, secrets, members, quotas, or audit logs receives HTTP `404 Not Found` (`error_code: RESOURCE_NOT_FOUND`), byte-identical to a non-existent resource lookup (`05-cross-workspace-negative-404.json`).
    - **Logs & Artifacts Isolation:** Non-members attempting to read `/v1/apps/{id}/logs`, `/v1/jobs/{id}/logs`, or `/v1/jobs/{id}/artifact` across workspaces receive HTTP `404 Not Found`; MinIO object keys are strictly workspace-prefixed (`workspaces/{workspace_id}/jobs/{job_id}/attempts/{attempt_number}/output.txt`).
    - **4-Role RBAC Hierarchy (`VIEWER < DEVELOPER < ADMIN < OWNER`):**
      - `VIEWER` can inspect apps, jobs, logs, artifacts, secrets metadata, and quotas, but receives `403 Forbidden` (`error_code: FORBIDDEN`) on any mutation (`03-viewer-secret-403.json`) or audit export.
      - `DEVELOPER` can create/deploy apps, trigger builds, submit/cancel/rerun jobs, and create/rotate secrets, but receives `403 Forbidden` on secret deletion, member mutations, and audit export.
      - `ADMIN` can delete secrets and export workspace audit logs (`13-workspace-a-audit-export.json`), and can manage `DEVELOPER`/`VIEWER` members, but cannot modify or remove `OWNER` or `ADMIN` members.
      - `OWNER` has full workspace administration privileges, guarded by last-owner protection (`409 Conflict` when attempting to demote or remove the last `OWNER`).
    - **Encrypted Secrets at Rest (AES-256-GCM + AAD Binding):**
      - Secret values are encrypted with AES-256-GCM (`v{version}:{nonce_b64}:{ciphertext_b64}`) using `workspace_id:secret_name` as Additional Authenticated Data (AAD) in `apps/api/app/core/crypto.py`.
      - Ciphertext swapped across workspaces or secret names fails GCM tag verification (`SecretDecryptionError`).
      - Plaintext is never returned by API endpoints (`SecretResponse` exposes only `id`, `workspace_id`, `name`, `key_version`, `created_at`, `updated_at`), and key rotation increments `key_version` (`04-secret-rotated.json`).
    - **Kubernetes Network & Container Isolation:**
      - `EnsureWorkspaceIsolation` (`runtime/internal/reconciler/kube_runner.go`) reconciles a per-workspace `NetworkPolicy` (`hc-netpol-{workspace_id}`, captured live in `10-k8s-networkpolicy.yaml`) that restricts Pod ingress to same-workspace pods (`hamicloud.io/workspace-id`) and `ingress-nginx`, and restricts Pod egress to same-workspace pods and DNS (`53/UDP`, `53/TCP`).
      - Reconciles namespace `LimitRange` (`hc-workload-limits`, captured live in `11-k8s-limitrange.yaml`) enforcing default CPU (`100m` request / `500m` limit) and memory (`128Mi` request / `512Mi` limit) bounds.
      - Applies hardened container `SecurityContext` (`allowPrivilegeEscalation: false`, `capabilities.drop: ["ALL"]`, `seccompProfile.type: RuntimeDefault`, captured live in `12-k8s-deployment-securitycontext.yaml`) to all service Deployments and Job Pods.

- [x] **A noisy workspace cannot bypass admission limits:**
  - Verified across Control Plane API admission, Redis rate limiting, and Go Scheduler fair round-robin admission:
    - **Control Plane Quota Enforcement:** Workspace quotas (`concurrent_jobs_limit=2`, `concurrent_builds_limit=1`, `deployed_services_limit=2`, `pending_operations_limit=100`) are enforced before accepting deployments, builds, or jobs (`429 Too Many Requests`, `error_code: QUOTA_EXCEEDED`, `Retry-After: 15`).
    - **Redis Fixed-Window Rate Limiter:** Per-workspace mutation rate limiting (`apps/api/app/core/rate_limit.py`) enforces `RATE_LIMIT_REQUESTS_PER_MINUTE` per workspace in Redis with `Retry-After` headers (`429 Too Many Requests`, `error_code: RATE_LIMITED`), isolating burst traffic from other workspaces.
    - **Go Scheduler Workspace Round-Robin Fair Admission:** `ScanQueuedJobs` (`runtime/internal/store/postgres.go`) uses `ROW_NUMBER() OVER (PARTITION BY j.workspace_id ORDER BY j.created_at ASC, j.id ASC) AS ws_rank` ordered by `ws_rank ASC, created_at ASC` to interleave queued jobs across workspaces in round-robin order, while `ClaimNextQueuedJob` atomically enforces `MAX_CONCURRENT_JOBS_PER_WORKSPACE` (default `2`) and creates a `CONCURRENT_JOB` `quota_reservations` row (`07-fair-admission-jobs.json`, `08-workspace-a-quotas.json`).
    - In the live M4 demo (`06-scheduler-fair-admission.log`, `07-fair-admission-jobs.json`), Workspace A submitted a burst of 4 jobs (`noisy-alpha-job-1..4`) and Workspace B submitted 1 job (`quiet-beta-job-1`); a single scheduler pass admitted `noisy-alpha-job-1` and `noisy-alpha-job-2` (reaching Workspace A's cap of 2 active jobs), held `noisy-alpha-job-3` and `noisy-alpha-job-4` in `QUEUED`, and immediately admitted Workspace B's `quiet-beta-job-1` without starvation.

## 2. Implemented Components & Deliverables

1. **Database Schema & 4-Role RBAC (`migrations/versions/0006_m4_quotas_secrets_audit.py`, `0008_add_admin_workspace_role.py`, `apps/api/app/core/auth.py`):**
   - `workspace_memberships`: 4-role hierarchy (`VIEWER < DEVELOPER < ADMIN < OWNER`) enforced via `ck_workspace_memberships_role` and `ROLE_HIERARCHY`.
   - `secret_references`: workspace-scoped encrypted secret storage (`workspace_id`, `name`, `encrypted_value`, `key_version`).
   - `quota_reservations`: active and released concurrency reservations (`CONCURRENT_JOB`, `CONCURRENT_BUILD`, `DEPLOYED_SERVICE`).
   - `audit_events`: immutable tenant audit log with cursor pagination and action/actor filtering.

2. **AES-256-GCM Secret Encryption & Key Rotation (`apps/api/app/core/crypto.py`, `apps/api/app/api/v1/secrets.py`):**
   - Versioned AES-256-GCM encryption (`v{version}:{nonce}:{ciphertext}`) with `workspace_id:secret_name` AAD binding to prevent cross-tenant or cross-secret ciphertext substitution.
   - `POST /v1/workspaces/{workspace_id}/secrets`, `GET /v1/workspaces/{workspace_id}/secrets`, `DELETE /v1/workspaces/{workspace_id}/secrets/{secret_name}` with `secret.created`, `secret.rotated`, and `secret.deleted` audit events.

3. **Workspace Quotas, Redis Rate Limiting & Audit Export (`apps/api/app/core/quotas.py`, `apps/api/app/core/rate_limit.py`, `apps/api/app/api/v1/quotas.py`, `apps/api/app/api/v1/audit.py`):**
   - `GET /v1/workspaces/{workspace_id}/quotas`: live workspace concurrency usage and active reservation inspection.
   - `GET /v1/workspaces/{workspace_id}/audit`: `ADMIN`-gated audit log export with cursor pagination.
   - `GET/POST/DELETE /v1/workspaces/{workspace_id}/members`: 4-role membership management with `ADMIN` delegation rules and last-owner protection.

4. **Go Fair Scheduler & Kubernetes Tenant Isolation (`runtime/internal/store/postgres.go`, `runtime/internal/reconciler/kube_runner.go`):**
   - Fair workspace round-robin job scanning (`ROW_NUMBER() OVER (PARTITION BY workspace_id ...)`) and per-workspace concurrency cap enforcement (`MAX_CONCURRENT_JOBS_PER_WORKSPACE`) with transactional `quota_reservations` tracking and automatic release on terminal states (`SUCCEEDED`, `FAILED`, `CANCELLED`, `DEAD_LETTERED`).
   - Automatic Kubernetes `NetworkPolicy` (`hc-netpol-{workspace_id}`), `LimitRange` (`hc-workload-limits`), and hardened container `SecurityContext` reconciliation on every workload deployment and job execution.

5. **Web Dashboard Governance & Security View (`apps/web/src/App.tsx`, `apps/web/src/api.ts`):**
   - Added **Governance & Security** tab displaying Workspace Quotas & Active Reservations, Encrypted Secrets management (`AES-256-GCM`), 4-role Workspace Members RBAC administration, and Audit Trail Export.
